# L.A.I.S.S. Dashboard

Next.js 14 (App Router) frontend for the [LAPD Crime Data Analysis](../README.md) project. Deployed to Vercel: https://lapd-data-crime.vercel.app/

## Setup

```bash
npm install
npm run dev     # http://localhost:3000
npm run build   # production build
npm run lint
```

## Environment variables

Copy `.env.example` to `.env.local` and fill in the values. Also set in the Vercel project for production.

| Variable | Used for |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase project URL (auth) |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase anon key (auth) |
| `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` | Google Maps JS API (`src/components/LaMapGoogle.js`) |

## Data flow

This app has **no backend API** — all analytics data is static JSON/GeoJSON under `public/data/` (34 files), generated offline by the Python pipeline in `../src/` and `../scripts/`. To refresh a layer: run the relevant generator script from the repo root, then commit the updated file(s) in `public/data/`.

Auth (Supabase) is the only runtime external dependency; `src/middleware.js` handles route protection, but the app currently ships as an open-access demo (guest login).

## Structure

```
dashboard/
├── src/
│   ├── app/            ← Routes (App Router): login, dashboard, osiris, insights, geo, compare, glossary
│   ├── components/     ← Charts (Recharts), maps (Google Maps + LaMap), filters, KPI cards, Sidebar/Shell
│   ├── lib/             ← filterUtils, geoAnalytics, supabaseClient
│   └── middleware.js    ← Route protection
└── public/data/         ← Static JSON/GeoJSON consumed client-side (generated by the Python pipeline)
```
